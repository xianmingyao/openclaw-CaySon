## 一、FDE 深度分析

### 1.1 什么是 FDE？

| 项目 | 内容 |
|------|------|
| **全称** | Forward Deployed Engineer |
| **中文** | 前沿部署工程师 / 驻场工程师 |
| **起源** | Palantir，2011年，为美国中情局和军方开发数据分析软件 |
| **本质** | 将AI技术转化为企业实际生产力的核心执行者 |

### 1.2 FDE 的诞生背景

```
问题：没有人知道间谍究竟是怎么工作的
       ↓
Palantir 派工程师驻场，深入业务一线
       ↓
工程师不仅要写代码，还要理解真实业务场景
       ↓
FDE 模式诞生
```

### 1.3 为什么企业 AI 落地越来越需要 FDE？

| 痛点 | 说明 |
|------|------|
| **模型与落地断层** | 模型能力狂飙，但企业部署步履蹒跚 |
| **不只是技术问题** | 数据、权限、合规、审计、旧系统、组织阻力 |
| **定制化陷阱** | 每个企业需求不同，无法用标准产品解决 |
| **快速响应需求** | 爆发式算力需求下，"远水救不了近渴" |

### 1.4 FDE vs 传统模式

| 维度 | AIDC（自建团队） | FDE（驻场模式） |
|------|-----------------|----------------|
| **性质** | 青训营，培养本土人才 | 雇佣兵，快速响应 |
| **速度** | 稳定但慢 | 快速到位 |
| **成本** | 便宜但固定 | 贵但按需 |
| **适用场景** | 长期、持续性需求 | 爆发式、紧急需求 |

> "AIDC是青训营，算力租赁是雇佣兵。本土培养固然稳定+便宜。但远水解不了近渴。爆发式的算力需求下，天价外援该请还是得请！"

### 1.5 FDE 的核心能力

1. **技术 + 业务的跨界能力**
2. **深入一线理解真实业务场景**
3. **不只是写代码，要找到**：
   - 指标（业务目标）
   - 规则（业务逻辑）
   - 流程（业务闭环）
4. **连接 AI 能力与企业实际需求**

## 二、业务访谈深度分析

### 2.1 视频核心五步法

| 序号 | 要点 | 核心含义 |
|------|------|----------|
| **1** | 明确目的 | 不是聊天，而是为**系统设计**找到指标、规则和流程 |
| **2** | 避开空泛问题 | 少问"你想要什么"，避免抽象答案 |
| **3** | 追问真实事实 | 用 **Mom Test** 思路，问过去发生过什么 |
| **4** | 拆出系统要素 | 从真实事件里提炼**指标、风险、责任人和闭环流程** |
| **5** | 用 AI 做准备 | AI 辅助理解行业和设计问题，但**答案来自真实业务** |

### 2.2 什么是 Mom Test？

**Mom Test** 来自同名书籍，核心思想是：**"如何问出连你妈妈都无法欺骗你的问题"**

| 传统问题 | Mom Test 问题 | 区别 |
|---------|--------------|------|
| "你想要什么？" | "上次遇到这个问题时，你怎么做的？" | ✅ 具体事实 vs ❌ 抽象偏好 |
| "你会用吗？" | "你为此付过多少钱？" | ✅ 真实行为 vs ❌ 口头承诺 |
| "这个功能好吗？" | "你上次用是什么时候？" | ✅ 可验证 vs ❌ 猜测 |

**三个核心原则**：
1. 谈论他们的**生活**，而不是你的想法
2. 问**过去的具体事实**，而不是未来的概念
3. **少说多听**

### 2.3 为什么 Mom Test 适合企业 AI 落地？

| 传统访谈 | 企业 AI 访谈的问题 | Mom Test 解法 |
|---------|------------------|--------------|
| 客户说"我想AI帮我分析数据" | ❌ 太抽象，无法落地 | ✅ "上次做这个决策花了多久？" |
| 客户说"我想要一个智能助手" | ❌ 需求不清 | ✅ "上周处理了多少工单？" |
| 客户说"AI应该能提高效率" | ❌ 无法量化 | ✅ "现在的流程哪里最费时间？" |

### 2.4 业务访谈的真正目的

```
不是收集需求清单
       ↓
而是找到系统设计的三个核心要素：
       ↓
┌─────────────────────────────────────┐
│  1. 指标（Metrics）                  │
│     → 业务目标是什么？如何衡量成功？   │
│                                        │
│  2. 规则（Rules）                    │
│     → 业务逻辑是什么？谁决定什么？     │
│                                        │
│  3. 流程（Processes）                │
│     → 事情是怎么流转的？闭环在哪里？   │
└─────────────────────────────────────┘
```

## 三、FDE 与业务访谈的关联

| 角色 | 核心任务 | 方法 |
|------|---------|------|
| **FDE** | 驻场落地 AI | 用 Mom Test 理解真实业务 |
| **业务访谈** | 收集系统设计要素 | 追问过去事实，提炼指标/规则/流程 |
| **AI 准备** | 用 AI 辅助理解行业 | AI 帮助准备背景知识，但答案来自真实业务 |

### 完整落地流程

```
┌─────────────────────────────────────────────────┐
│  1. 用 AI 做准备                                 │
│     → 了解行业背景、常见术语、竞品方案            │
├─────────────────────────────────────────────────┤
│  2. 明确访谈目的                                 │
│     → 不是聊天，是找到指标+规则+流程             │
├─────────────────────────────────────────────────┤
│  3. Mom Test 三问                               │
│     → 问过去事实，不问未来假设                   │
│     → 问具体行为，不问抽象偏好                   │
│     → 少说多听，让客户谈他们的生活               │
├─────────────────────────────────────────────────┤
│  4. 提炼系统要素                                 │
│     → 指标：业务目标 + 衡量标准                  │
│     → 风险：哪里容易出错？                      │
│     → 责任人：谁决定什么？                       │
│     → 闭环：流程从哪到哪？                      │
├─────────────────────────────────────────────────┤
│  5. AI 辅助落地                                 │
│     → 用 AI 整理访谈记录、设计方案               │
│     → 但真正的答案永远来自真实业务               │
└─────────────────────────────────────────────────┘
```

## 五、关键术语

| 术语 | 解释 |
|------|------|
| **FDE** | Forward Deployed Engineer，前沿部署工程师/驻场工程师 |
| **Mom Test** | 一种用户访谈方法，问出无法被欺骗的具体事实问题 |
| **AIDC** | AI Infrastructure Data Center，AI算力基础设施 |
| **本体（Ontology）** | 企业AI中指业务知识的形式化表示 |
| **指标（Metrics）** | 业务目标的数量化衡量标准 |
| **规则（Rules）** | 业务逻辑和决策条件 |
| **流程（Processes）** | 业务的闭环流转路径 |
