## 二、MCP适配层

### 2.1 MCP是什么
MCP（Model Context Protocol）= 工具调用的适配层协议

### 2.2 核心职责
```
┌─────────────────────────────────────────────────────────────────────┐
│                        MCP适配层职责                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. 工具协议        统一工具调用格式                                 │
│  2. 参数校验        检查输入参数是否符合工具要求                       │
│  3. 权限控制        判断用户/Agent是否有权调用该工具                   │
│  4. 超时控制        单次工具调用超时处理                              │
│  5. 操作审计        记录所有工具调用日志                              │
│                                                                      │
│  核心价值：实现工具的可插拔、可治理、可扩展                            │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 为什么需要MCP
- 工具越来越多，需要统一管理
- 不同工具协议不同，需要标准化
- 治理和审计要求

## 三、模型写库 vs 模型读库

### 3.1 核心区分

| 维度 | 写库（Tool Calling） | 读库（RAG） |
|------|---------------------|-------------|
| 方向 | 模型→外部系统 | 外部知识→模型 |
| 模型行为 | 生成操作意图+参数 | 检索+生成 |
| 后端职责 | 校验、权限、事务、审计 | 向量召回、重排、生成 |

### 3.2 模型写库的后端职责
```
用户请求 → 模型生成意图 → 后端校验 → 权限判断 → 风险确认 → 事务控制 → 操作审计
```

**关键点**：模型只负责生成意图和结构化参数，后端必须做完整校验。

## 四、Agent工作模式

### 4.1 三种主流模式

| 模式 | 说明 | 适用场景 | 越靠近业务的特点 |
|------|------|---------|----------------|
| **ReAct** | 推理+执行交替 | 复杂推理任务 | Agent越不自由 |
| **Plan and Execute** | 计划→执行分离 | 多步骤任务 | 需预定义计划 |
| **Workflow** | 固定流程 | 线上业务 | 最不自由，强约束 |

### 4.2 模式选择原则
```
越靠近线上业务，Agent越不自由
- 金融/医疗：必须强约束（Workflow优先）
- 内部工具：适中约束（ReAct/Plan）
- 研究/探索：弱约束（ReAct）
```

## 五、RAG检索增强生成

### 5.1 RAG解决什么问题
解决模型知识不足问题（幻觉、知识陈旧）

### 5.2 完整RAG链路
```
┌─────────────────────────────────────────────────────────────────────┐
│                        RAG完整链路                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  数据接入 → 数据清洗 → 文档切片 → 向量 Embedding → 向量召回         │
│       ↓                                                        ↓    │
│                                                            rerank重排 │
│                                                                  ↓    │
│                                                               生成答案  │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.3 各环节详解

**文档切片（Chunking）**
- 固定大小切片（512/1024 tokens）
- 语义切片（按段落/句子）
- 重叠切片（保证连续性）

**Embedding向量化**
- 将文本映射为高维向量
- 常用模型：text-embedding-ada-002、BGE、M3E
- 向量维度：768/1024/1536

**向量召回**
- ANN近似最近邻检索
- 工具：Faiss、Milvus、Qdrant
- 指标：余弦相似度/内积

**rerank重排**
- 第一轮召回可能不精准
- rerank用更精准模型重排
- 常用模型：bge-reranker、Cohere rerank

## 六、长期记忆 vs 短期记忆

### 6.1 核心区分

| 维度 | 短期记忆 | 长期记忆 |
|------|---------|---------|
| 作用域 | 当前会话 | 跨会话 |
| 解决什么问题 | "这轮别断片" | "下次还能记得你" |
| 实现方式 | 会话上下文窗口 | 持久化存储+检索 |
| 容量 | 受限于context window | 理论上无限 |

### 6.2 短期记忆压缩

**触发条件**：
1. 上下文token接近上限
2. 会话轮次太长
3. 任务进入新阶段

**处理方式**：
```
┌─────────────────────────────────────────────────────────────────────┐
│                    短期记忆压缩策略                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  保留原文       关键信息（如用户偏好、任务目标）                       │
│       ↓                                                               │
│  压缩摘要       智能压缩：让模型总结历史上下文                         │
│       ↓                                                               │
│  丢掉无效日志   机械压缩：按规则裁剪（如最后N轮）                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.3 两种压缩方式

| 压缩方式 | 说明 | 优缺点 |
|---------|------|--------|
| **智能压缩** | 让模型总结历史上下文 | 质量高，但消耗token/费用 |
| **机械压缩** | 按规则裁剪（如保留前3轮+后1轮） | 速度快，但可能丢失关键信息 |
| **混合压缩** | 生产环境常用 | 智能+机械结合 |

## 七、多智能体模型选型

### 7.1 分层模型使用原则
```
┌─────────────────────────────────────────────────────────────────────┐
│                    多智能体模型分层选型                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  简单任务 ──────→ 小模型（GPT-4o-mini、Qwen-turbo）                 │
│           速度快、成本低、足够准确                                   │
│                                                                      │
│  复杂任务 ──────→ 强模型（GPT-4o、Claude-3.5）                      │
│           推理能力强、泛化好                                        │
└─────────────────────────────────────────────────────────────────────┘
```

### 7.2 选型考量
- 任务复杂度
- 延迟要求
- 成本控制
- 推理能力需求

## 八、熔断机制

### 8.1 为什么Agent需要熔断
Agent执行路径不固定，可能出现：
- 无限循环
- 单步卡死（死循环调用工具）
- 资源耗尽

### 8.2 熔断三要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **最大执行步数** | Agent最多执行N步 | max_steps=10 |
| **单次调用超时** | 每次工具调用的超时 | timeout=30s |
| **总任务超时** | 整个任务的生命周期 | total_timeout=300s |

### 8.3 熔断后处理
```
┌─────────────────────────────────────────────────────────────────────┐
│                        熔断错误处理                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  错误类型1：超时 → 重试1次 → 仍超时 → 降级返回                       │
│  错误类型2：权限拒绝 → 直接返回"无权限"                              │
│  错误类型3：工具不存在 → 返回"功能不可用"                            │
│  错误类型4：业务异常 → 记录日志 → 返回友好错误                        │
└─────────────────────────────────────────────────────────────────────┘
```

## 九、综合面试题速记

### 9.1 MCP适配层（必问）
> "MCP适配层负责工具协议、参数校验、权限控制、超时和审计，实现工具的可插拔、可治理、可扩展。"

### 9.2 模型写库（必问）
> "模型只生成操作意图和结构化参数，后端需要进行校验、权限判断、风险确认、事务控制和操作审计。"

### 9.3 Agent工作模式（必问）
> "Agent工作模式包括ReAct、Plan and Execute、Workflow。越靠近线上业务，Agent越不自由。"

### 9.4 RAG链路（必问）
> "RAG解决模型知识不足问题，基础链路包括数据接入、清洗、切块、向量Embedding、召回、rerank重排和生成。"

### 9.5 记忆系统（必问）
> "短期记忆服务当前会话，解决'这轮别断片'；长期记忆服务跨会话，解决'下次还能记得你'。"

### 9.6 记忆压缩（必问）
> "短期记忆压缩触发条件是上下文token接近上限、会话轮次太长、任务进入新阶段。处理方式是保留原文、智能压缩摘要、机械压缩裁剪，生产中混合使用。"

### 9.7 多智能体模型选型（必问）
> "多智能体场景模型选型要分层使用，简单任务用小模型，复杂任务用强模型。"

### 9.8 熔断机制（必问）
> "Agent需要有熔断机制，限制最大执行步数、单次调用超时、总任务超时，根据错误类型处理。"
