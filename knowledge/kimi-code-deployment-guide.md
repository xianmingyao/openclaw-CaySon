## 🎯 这是什么

**Kimi Code** 是由 **月之暗面（Moonshot AI）** 开源的 **Coding Agent**（编程智能体）工具，是 **Claude Code 的国内平替**。

最大优势：
- ✅ **不需翻墙**（国内用户友好）
- ✅ **一行命令安装**
- ✅ **内置最新开源模型 Kimi K2.7 Code**
- ✅ **编程能力比 K2.6 有真实提升**，缩小与国外一线模型差距
- ✅ **支持自由切换不同供应商和模型**

## 📦 核心功能与特色玩法

### 1️⃣ 视频理解（ReadMediaFile 工具）

**内置工具**：ReadMediaFile — 可以把**图片或视频以多模态内容发送给模型**。

**实战案例**：分析 2022 卡塔尔世界杯比赛视频

```
操作：直接把视频拖进 Kimi Code
Prompt: 你看看这是哪一年的比赛？谁跟谁的？
```

Kimi Code 会：
- 识别出 **2022 年卡塔尔世界杯**
- 描述第一个进球的场景
- 报告**比赛总共有 8 个进球**
- **把每个进球的时间都标注出来**
- 把 8 个进球保留 1 秒时间片段 → 拼接成 1×8 = 40 秒的精彩集锦
- 配背景音乐

> 视频 → 语义理解 → 拆解 → 二次创作，一条龙。

**用途**：通过自然语言**直接查询股票、企业工商信息、学术文献**等。

**安装方法**：

```
输入 /plugin → 找到官方插件合集 → 选择 Kimi Data Source 安装
输入 /skill → Kimi data source → 启动
```

**6 种数据源**：
- 股票
- 企业工商信息
- 学术文献
- 等

**实战案例**：绘制黄金/白银/美股/A股/港股近一年走势图

```
任务：检查一下黄金白银美股 A股 港股 近一年的走势，绘制一个归一化的走势图
```

效果：
- Data Source 查到**非常精准的历史走势**
- 调用 **Python 绘图功能**
- 绘制出**归一化走势图**（消除量级差异，直接看趋势）
- **各个指标的趋势图一对比，一目了然**

### 3️⃣ 角色与命令：3 种工作模式

#### 🔹 Auto 模式（高安全 + 高便利）

```
输入 /auto → 进入 Auto 模式
```

- AA 会对**工具调用、文件修改进行自动审批**
- **获得高安全性的同时**，**极大提升使用便利度**

#### 🔹 YOLO 模式（更激进）

```
输入 /yolo → 进入 YOLO 模式
```

- AA 会**跳过所有的审批确认**
- **7.5 分钟完成大任务**（任务复杂度高时）
- **仅推荐用于熟悉的任务**

#### 🔹 btw 命令（临时子 agent 提问）

```
输入 btw 你的问题
```

- btw = **by the way** 的缩写
- **可以临时生成一个子 agent**
- 子 agent 能够看到当前对话历史
- 但**不会修改上下文** + **不会调用工具**
- **非常适合用来临时提问技术问题**

**示例**：

```
btw 你是用什么工具处理视频的？
→ kimi code 回答：我是用 ffmpeg 对视频进行切分组合
```

> 这个回答不会污染主对话上下文。

### 4️⃣ Swarm Mode（群组模式）

**能力**：Kimi Code 能将**大型的复杂任务**，**拆分成更小的子任务**，**启动专门的子代理进行处理**，并将所有的输出**整合成一个最终结果**。

```
输入 /swarm → 开启群组模式
```

**适用场景**：**可以并行执行的任务**。

**实战案例**：6 篇 AI 领域高影响力论文 → 设计统一的视觉风格 → 制作成"复杂风格"专题页

```
Prompt: 我要你使用 Swap Mode，使用 Kimi Datasauce
        先下载这 6 篇论文
        然后设计一个统一的视觉风格
        把这些论文做成复杂风格的专题页
        并行制作专题页
        最后汇总到一个文件里面
```

执行流程：
1. **主 agent 启动 3 个 subagent 的 swarm**
2. **分头下载 6 篇论文**
3. **论文下载完毕后**，**消息再汇总到主 agent**
4. **主 agent 再次启动 swarm**
5. **分配 3 个 subagent** → **分头制作专题页**
6. **最后主 agent 把做好的专题页汇总到一个文件里面**

效果：
- **复杂的编码效率提高**
- **每篇论文都配了独特的主题色**
- 保持了样式稳定
- **整体风格既简单又大气美观**

### 5️⃣ Go 模式（多轮迭代专用）

**Kimi K2.7 Code 专门优化了 Go 模式**。

```
输入 /go → 启动 Go 模式
```

**适用场景**：
- **任务需要多轮迭代**
- **有可验证的方法**（如 Playwright CLI 操作浏览器来验证）
- **有明确的目标**（如"玩法"和"画面"越像/越好）

**实战案例**：青蛙过河游戏

```
Prompt: 跟目录有一个青蛙过河的图片，我要你用单个 HTML 跑这个游戏
        然后用 Playwright CLI 测试 + 完善 + 迭代
        保留每一轮的历史截图
```

执行流程：
- **Kimi 跑了 14 分钟**
- **进行了 5 轮迭代**
- **最终完成了目标**
- **可以在历史截图里面看到**，**每轮迭代以后**，**画面的质感变得越来越好**
- **试玩功能正常，效果很好**

### 6️⃣ Skills 系统（自定义技能包）

**Skills = 给 AA agent 的一个专业技能包**（或者说是**一种带目录的说明书**）。

**用途**：**把工作流、专业能力或者某些规则，封装定制成一个个 Skills**，**交给 AA agent**。**Agent 在执行特定任务的时候更稳定**，**更高效，输出也更可靠**。

**实战案例**：浏览器自动化 skill（Playwright CLI）

```bash
# 1. 创建一个项目文件夹
# 2. 执行这两个命令
#    - 配置下 Playwright CLI
#    - 还有对应的 skill

# ⚠️ 重要：要把项目目录里存放 Skills 的文件夹名从 .cloud 改成 .agents

# 3. 启动 Kimi Code 测试
# 输入提示词：
# 使用 Playwright 打开谷歌，搜索一下青岛天气，要加上刚才 Update 的参数
```

Kimi Code 成功操作浏览器打开了谷歌，并且搜索到了天气。

**修复任务**：直接把这个 issue 的地址发给 Kimi Code。

**执行过程**：
- 模型选择：Kimi API 平台接入的 K2.7 Code
- Kimi 读了这个 issue
- 定位到了相关的代码
- **规划了 3 个 todolist**
- 然后**逐项完成**
- 提供了**两种方便的工具调用审批模式**（Auto 模式）
- 用了 **7.5k 上下文窗口**（13%）

**Kimi Code 用了 7.5k**（13% 的上下文窗口），就完成了任务。

### 案例 2：性能对比 Kimi vs Claude Opus 4.8

**对比条件**：用 OpenRouter 接入 Claude Opus 4.8 的 API，**同样的提示词**。

**Opus 4.8 表现**：
- 8 分钟后说完成了任务

- 把 Opus 4.8 的思考强度从默认调成 High

- 这次成功了
- 由于 OpenRouter 不统计缓存，无法对比缓存指标

**Kimi 表现**：4 个指标都更好

| 指标 | Kimi K2.7 Code | Claude Opus 4.8 | 谁更优 |
|------|----------------|-----------------|--------|

| 用时 | < 8 分钟（含 1 轮）| 8 分钟 + 2 轮 | ✅ Kimi |

| **总成本** | **明显低于** | 高 | ✅ Kimi |

**97% 缓存命中率意味着什么？**

> 对于 Coding Agent 来说，**高缓存命中率意味着它能很好地复用上下文**，**成本更低**，**上下文利用更充分**，**多轮协作更稳定**，**更适合处理大型代码库和长流程的开发任务**。

## 🛠️ IDE 集成（Z IDE + ACP 协议）

### 什么是 ACP 协议？

**ACP = Agent Communication Protocol**（智能体通信协议）

> Kimi Code 原生支持 ACP 协议。**这是一套给代码编辑器和编程 agent 之间协作的通信协议**。

### 以 Z IDE 为例的集成步骤

```
1. 在电脑上安装 Z（IDE）
2. 打开 Z
3. 点击右上角的三个点
4. add custom agent
5. 把 ouragent 这一段替换成 Kimi code 的配置
6. 保存
7. 回到 agent 面板
8. 打个招呼（输入任意消息）
9. 得到了回复，就配置成功了
```

> 这样做就可以**一边跟 AA 对话，一边查看修改代码**。

## 🚀 部署使用注意点

### 安装时
1. 官网下载对应系统的安装命令
2. 终端粘贴执行
3. 安装完成后，**输入 `kimi` 启动**
4. 首次启动会提示登录

### 配置时
1. **推荐用 Auto 模式**（高安全 + 高便利）
2. **不要把 YOLO 模式当默认**（会跳过所有审批）
3. **大型项目用 4.5 Anstar 类似的实际 issue 验证**（而非人工测试）

### Skills 开发时
1. **项目目录下存放 Skills 的文件夹名是 `.agents`（不是 `.cloud`）**
2. 浏览器自动化推荐用 Playwright CLI
3. Skills 是**带目录的说明书**，**封装工作流 + 专业能力 + 规则**

### Swarm 模式
1. **适用于可并行任务**（如多论文处理、多模块开发）
2. 先主 agent 拆分 → subagent 并行 → 主 agent 整合
3. **每轮迭代都看下结果质量**

### Go 模式
1. **必须配合可验证方法**（如 Playwright 截图 + 反馈）
2. **必须明确目标**（如"画面越来越好"）
3. **保留每轮历史截图**（用于复盘）

### ACP 协议集成
1. **确认 IDE 是否支持 ACP**（Z IDE 已支持）
2. **配置 custom agent** 时替换 ouragent 段
3. **配置成功后打个招呼**测试连通性

## 🕳️ 避坑指南

### 🔴 坑 1：Skills 文件夹名搞错

**问题**：把 Skills 文件夹命名为 `.cloud`，导致 Kimi Code 找不到。

**解决**：**改成 `.agents`**，这是 Kimi Code 的约定。

### 🔴 坑 2：YOLO 模式误用

**问题**：在生产环境用 YOLO 模式，导致不可控修改。

**解决**：
- 默认用 Auto 模式
- YOLO 模式**只在熟悉的任务上用**
- 重要项目**永远用人工审批**

### 🔴 坑 3：视频分析的 ffmpeg 路径

**问题**：Kimi Code 处理视频时用 ffmpeg，但**默认没装**。

**解决**：
- Mac: `brew install ffmpeg`
- Windows: 下载 gyan.dev 的 ffmpeg
- Linux: `apt install ffmpeg`

### 🔴 坑 4：Swarm 模式任务拆分不合理

**问题**：拆分粒度太细 → subagent 之间通信成本高；拆分粒度太粗 → 失去并行意义。

**解决**：
- **每个子任务可独立完成**（无强依赖）
- **每个子任务的输入输出明确**
- **主 agent 负责整合而不是重做**

### 🔴 坑 5：Go 模式无明确目标

**问题**：没有明确"什么是好" → 5 轮迭代后模型还在原地打转。

**解决**：
- **必须有可验证的方法**（如截图对比、单元测试）
- **必须有明确目标**（如"画面越来越像某参考图"）
- **保留每轮历史**，便于复盘

### 🔴 坑 6：直接当 Claude Code 替代

**问题**：以为 Kimi Code = Claude Code，套用同样的工作流，结果踩坑。

**解决**：
- Kimi Code 有**自己的特色功能**（视频理解、Data Source、Swarm、Go）
- **不要硬套 Claude Code 的使用习惯**
- 优先探索 Kimi Code 原生能力

```bash
# 基础
kimi                    # 启动 Kimi Code
/help                   # 查看帮助
/exit                   # 退出

/login                  # 登录/切换账号
```
